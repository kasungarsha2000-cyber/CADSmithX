Layout Sketches and Top-Down Assemblies Without the Tangles

Driving a whole machine from one skeleton, and keeping the references under control

Table of Contents

  • A skeleton part, not a web of references
  • If you do use in-context references

Key takeaways

  • Keep driving geometry in a dedicated skeleton part.
  • Let references flow from the skeleton to the components.
  • Test a working-height change before handing the model over.

A machine layout has a handful of numbers that everything else obeys: working height, pitch between stations, the centres the frame is built around. Top-down design puts those numbers in one place and lets the parts follow. Done carelessly, it also welds every part to every other part through in-context references, and a small change sets off a chain of rebuild errors.

A skeleton part, not a web of references

The approach that survives handover is a dedicated skeleton: one part containing only sketches, planes and axes that describe the layout. Insert it first into the assembly and fix it at the origin. Every other component references the skeleton, and nothing references anything else. References then flow one way, which means a change has one predictable path through the model.

  1. Create the skeleton part with the main centre lines, working planes and key points.
  2. Name the driving dimensions as global variables and gather them in one equation set.
  3. Insert the skeleton into the assembly, fixed at the origin.
  4. Build or insert each component and mate it to skeleton geometry — planes and axes, not neighbouring faces.
  5. Where a part must take its shape from the layout, use Convert Entities from the skeleton sketch rather than sketching on a neighbour.
Layout blocks for the concept stage

For early arrangement work, an assembly Layout sketch with blocks is quicker still. Draw each station as a block, drag them until the arrangement works, then make parts from the blocks. It is an excellent way to agree a footprint with a client before committing to detail.

If you do use in-context references

In-context features are genuinely useful for a bracket that must fit whatever it lands on. The risk is that the reference is to a face that later disappears, leaving a dangling relation. A few habits keep them honest: create the reference to stable geometry, lock the external reference once the shape is settled, and list external references before you hand the model over so the next person knows where the ties are.

The test of a layout-driven model is simple. Change the working height by 50 mm. If the frame, the guards, the conveyor interface and the drawings all follow without a single error, the references are pointing the right way. If the tree turns red, the model was holding itself together by luck.
